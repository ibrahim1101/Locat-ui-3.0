# Private conversation foundation — partial P0

The production API now reserves one private room per accepted local account pair. The caller supplies only a contact account ID and its memory-held Matrix token through the existing authenticated/proved Link endpoint. Cookie, device proof, Matrix token and Locat session must agree. The server chooses Matrix room version 12, private invite-only membership, `m.federate: false`, Megolm encryption, joined-only history and restrictive state/invite power levels. Creator power is implicit in v12; the creator must not appear in the users power-level map. Matrix v12 hash room IDs and legacy domain-qualified room IDs are recognized.

Schema 15 adds only `matrixConversations`, storing pair IDs, an opaque operation ID, pending/ready status, room ID and creation time. No raw token, private key or message plaintext is stored. Reservations precede network work. Reverse/concurrent requests discover the same row. A timeout, malformed/oversized response, server rejection or process interruption leaves pending state: automatic retry will not create a second room. Reconciliation and orphan cleanup are unfinished. Ready rooms survive restart. Older binaries must not be used to migrate schema 15 backwards; operator backup/restore remains explicit.

Gateway room operations require registry membership and current accepted/unblocked contact policy before and after upstream waits, in addition to the existing proof/session/token rechecks. Room joins accept no arbitrary fields. State/membership reads are scoped to that room. History pages are capped at 50, use a forced encrypted-event filter and retain the 2 MiB response cap. Sends permit only bounded standard Megolm envelopes, exact bound sender device/curve-key pins and bounded transaction IDs. The homeserver owns transaction idempotence; acknowledgement means accepted by the server, not that a recipient read or decrypted it. Plaintext sends, state writes, invites, aliases and arbitrary rooms remain unavailable.

Local validation: type/lint/build; 250 frontend tests/62 files, 107 backend tests. Real Synapse 1.163.0 + SDK 44.0.0/Rust 18.9.0 acceptance creates the production private room, checks state, discovers it from either contact, sends SDK ciphertext through the guarded gateway, decrypts on the recipient, retries the same transaction and gets the same event ID, reads ciphertext history and rejects removed-contact/plaintext traffic. Actual production HTTPS API tests use real Locat cookies, proof and bindings for creation, discovery, join, state, foreign token/Origin and blocked-contact denial.

This is not complete browser messaging. The first partial transport scenario used direct isolated Synapse for key distribution and recipient sync; the protected follow-on below now exercises those paths through the gateway. Account-scoped persistent UI lifecycle, per-send verified-device/membership/rotation policy, Send/Receive/history rendering, bounded uncertain-send recovery, actual browser acceptance, reconciliation and independent security review remain required. Browser Send is disabled. No federation, public exposure, international network, TURN or native compatibility claim is made.

Primary protocol references: https://spec.matrix.org/v1.19/client-server-api/ and https://spec.matrix.org/latest/rooms/v12/ . Exact implementation tests use the pinned local SDK/server, not assumptions from documentation alone.

## Protected transport follow-on

The gateway now accepts bounded standard Olm encrypted to-device messages to exact active bound self/contact devices. Sender/recipient curve pins must match. Standard SDK message IDs are bounded. Key-withheld notices contain only allowed protocol metadata and a server-normalized reason; plaintext room keys, arbitrary fields, wildcard devices and arbitrary recipients are rejected. Public device-key responses exclude inactive/unbound devices and fail if current keys differ from the bound signing/curve pins. Recipient authorization is rechecked after network waits.

Explicit `locat_conversations=1` sync overrides the upstream filter with at most 100 registered, currently accepted rooms and 50 timeline events per room; the existing 2 MiB response cap remains. The gateway strips nonregistered rooms, plaintext message events, ephemeral/account data and presence. Only active bound sender keys can deliver encrypted to-device events or supported withheld metadata. Default verification sync remains room-free. The caller must request a fresh/full initial state once when changing mode; forcing full state every sync caused a hot loop/rate-limit failure in an earlier test and is not retained.

Two real SDK clients now pass complete protected-gateway encryption/key distribution/sync/send/decryption, offline recipient delivery after an actual homeserver restart, duplicate suppression, tamper rejection and revoked-device sync denial. Production HTTPS additionally passes complete encrypted messaging with real Locat cookie/proof/bearer guards. Both database/WAL plaintext scans pass. These supersede the earlier direct-key-distribution limitation for the added scenarios only. Source tests now total 252 frontend/63 files and 111 backend, with type/lint/build passing.
