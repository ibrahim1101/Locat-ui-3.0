# Durable Link-to-Matrix revocation

Revoking a Link device now records upstream cleanup intent for its stored Matrix binding in the same SQLite transaction as key revocation, pairing invalidation and transfer/Remote cleanup. The Matrix grant is expired in that transaction. If queue insertion fails, the entire revocation rolls back and the API returns failure. After commit, Link proofs are invalidated. All normal gateway authorization still checks the current Link device and session; waiting for upstream cleanup does not permit continued gateway access.

Additive schema 13 creates matrixRevocations and a due-job index without deleting account, binding, key-pin, media or history data. Migration backfills bindings whose Link identities were already revoked and expires their local grants. Each job captures only the local account/Link device, Matrix user/device identifiers, status, attempt count, lease and timestamps. It stores no Matrix token, service credential, password or private key. There is at most one job per account/Link device.

The worker starts only when the operator has configured the existing validated managed application service. It runs immediately and every five seconds, processes at most four jobs per pass and performs one deletion at a time per process. A transactional 30-second lease prevents concurrent processes from claiming the same job. Lease tokens reject stale completion; a crashed worker's intent becomes claimable after lease expiry. The upstream request has a ten-second deadline. Failures retry after five seconds, then exponential delays capped at one hour, without claiming success. Shutdown stops scheduling, waits for an outstanding deletion and then closes SQLite.

Before deletion, the worker verifies that the Link identity remains revoked and that the current stored binding matches the queued target. The provisioner independently derives the only permitted Matrix user/device from this instance UUID, account, Link ID and configured Matrix authority. A mismatched/manual identity is never sent to the upstream service and is marked for manual cleanup. Configuration changes that no longer match a queued identity require operator review. Jobs remain pending while no managed service is configured; this does not imply a homeserver was contacted.

Standard application-service DELETE of the exact device invalidates all tokens for that Matrix device. A successful response or exact 404 M_NOT_FOUND confirms the deletion; other errors remain pending. Completion/manual outcomes and their audit records commit atomically. Already downloaded content and local/private keys are not wiped. Previously authorized network actions cannot be undone.

UI3 Devices uses its existing themed cards, confirmation Sheet, Button and refresh polling. Revoked cards distinguish pending cleanup, confirmed Matrix-device revocation and manual server sign-out. Self-revocation still blocks the current device view; another authorized device can inspect its status. The current-device Matrix settings action remains available separately. Queue status does not assert account-wide sign-out, remote file deletion or physical-device state.

Tests cover v12 migration/backfill and preserved bindings, atomic rollback when queue insertion fails, durable retry across database reopen, competing database connections, expired-lease completion rejection, exact identity scope, idempotent deletion, manual fallback, shutdown waiting and UI status wording. Real Synapse acceptance through the actual HTTPS/auth/proof server now revokes a Link identity and waits for its Matrix token to become invalid upstream.

Schema 14 adds pre-issuance managed-device intent, including cleanup before binding, operation leases and late-settlement re-arming; see MATRIX_MANAGED_SETUP.md. No raw-token inventory is stored.

Remaining work includes historical unrecorded sessions, account-wide token/session policy, operator handling for manually linked/changed-authority identities, actual browser/native acceptance and full cross-signing/identity recovery. The conversation gate remains closed. No public service or operator configuration was activated by this change.
