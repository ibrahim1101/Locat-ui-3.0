# Locat UI scope rework

**Current source of truth for the October 2026 scope rework.** Older roadmap, design, QA, and engineering-history documents describe earlier implementations. They remain for provenance and must not be read as confirmation that the retired modules or endpoints are active.

## Product scope

The app is organized around Chat, Link, Files & Vault, and the surrounding Locat workspace. The official Locat logo stays unchanged. Obsidian Ember is the default theme: matte `#0B0B0C` canvas with `#E86B2C` accent, consistent with the existing titanium and ember design system.

The navigation groups related destinations. Files opens a nested section for Vault and Secrets. Settings are grouped by account, app, connection and about, with a focused detail view; live account settings separate profile, sessions, security and messaging devices. Navigation, Home, Search, command palette, and module cards use the same hierarchy.

## Removed standalone features

- Cinema, media-library playback, Music, audio library/equalizer, and Photos library/editor.
- Host media scanning, streaming, media-library sharing, and media-specific server endpoints.
- Remote-control UI and Link remote-signaling endpoints.
- SentinelLab, incident/webhook ingestion, vendor mappings, tokens, incident screens, and related integration code.

The Search view scopes app destinations. A nested in-conversation search finds text and attachment names in up to 200 messages already loaded and decrypted on that device; it does not search the server, persist terms, or reveal ciphertext. Chat supports ordinary encrypted file attachments in verified one-to-one Matrix conversations; bytes are encrypted in the browser before upload, attachment keys travel inside the encrypted room event, and ciphertext integrity is checked before decryption. The nested composer groups Photo, Document or file, Video, Location & schedule, and Stickers & doodles by intent. Image review offers the original or one of three local resize presets; video review provides a local non-autoplay preview and original-only send. Voice recording is local, limited to 60 seconds and 2.9 MB, and requires explicit review before encrypted upload. The doodle sheet supports local drawing and sends a PNG through the same encrypted attachment path; the sticker picker offers twelve local designs across nested packs and also sends PNG attachments. Both use the same 2,900,000-byte cap. One-time location share is available only in a ready private conversation; it asks for device location after an explicit tap, defaults to rounded approximate coordinates, and sends the reviewed map link through the encrypted message path. Decrypted image/video/audio previews load on demand in message bubbles and never auto-play. All attachments use the existing Matrix encryption and uncertain-send protections, with a 2,900,000-byte cap. Read receipts are an account preference, off by default, sent only when a decrypted incoming message is visible in the open conversation at the latest scroll position, and enforced by the Matrix gateway; senders see a read status after the peer's receipt arrives. Typing indicators are a separate account preference, off by default; opted-in users exchange short-lived standard Matrix typing metadata in authorized private rooms. Draft contents are never sent, and each side must opt in to share or see the signal. Chromium and Firefox browser acceptance verifies encrypted attachment upload/download, byte equality, image preview, and storage behavior; real microphone acceptance is Chromium-only. Hosted two-account Matrix acceptance on run 39480102015 passed one-time location sharing, doodle delivery and sticker-pack delivery through the encrypted conversation; both Chromium and Firefox browser suites passed 7/7. Physical device acceptance remains open. Attachment handling is not routed through a standalone library. Link pairing and encrypted file/text transfers remain. Account activity remains under Settings → Security and uses the existing account events endpoint.

## Reconstructed live modules (local implementation)

The restored branch checkpoint did not contain the previous local-only Calendar, Workspace, Automate and Share code. Those modules are being rebuilt from the retained product intent. Current source includes:

- **Calendar:** personal and workspace-shared event create/edit/delete, fixed 24-hour/7-day recurring series, month ranges, optimistic revision checks and in-app reminders. Shared calendars are limited to active workspace members; workspace deletion removes their events. Editing or deleting an occurrence affects the full series. The app-level reminder monitor runs only while the browser is open, visible, unlocked and able to reach the server. Event titles, notes and schedule data are readable by the Locat server; OS notifications and E2EE are not available.
- **Automate:** one-time and fixed 24-hour/7-day recurring account reminders with edit/pause/delete and a cross-tab server dispatch guard. Missed repeat intervals coalesce into one delivery and advance to the next future occurrence. Reminder text is readable by the Locat server. Delivery requires a signed-in, unlocked, visible Locat app and a working server connection; arbitrary scripts and OS notifications are not supported.
- **Workspace:** account-owned teams, pending invitations, owner/admin/member roles, owner transfer, owner-only deletion, member JSON export, shared notes and task status. Deletion removes the workspace, memberships, invitations and board items atomically. Export is limited to active members and includes the workspace, members/invitations and the bounded 500-item board. Notes, tasks, membership and invite data are readable by the Locat server.
- **Share:** browser-encrypted text links using AES-GCM, selectable 1-hour/1-day/7-day expiry, a server-enforced 1/5/20/100 open limit, local key in the URL fragment, optional separate passphrase protection through a PBKDF2-wrapped content key, public ciphertext retrieval through a signed-out viewer, owner revocation, downloadable QR codes, and a PWA share target for text/title/URL handoff. Passphrases and plaintext stay in the browser; users send the passphrase through a separate trusted channel. Open counts are consumed atomically, successful responses are no-store, and anonymous retrieval is rate limited. The Share screen exposes the browser's install prompt when available and explains the install-menu fallback. QR generation and PWA staging happen on-device. Incoming PWA content is held in service-worker IndexedDB for up to one hour, opened by an opaque one-use ID, and remains local until the signed-in user reviews and creates an encrypted link. Links are bearer secrets; anyone who receives the full URL and any required passphrase can decrypt. Current limits are 1.5 MB plaintext, 20 active links per account, and 100 opens per link maximum. File links are not implemented.

These are code-complete first slices, not a production release claim. Automated UI tests cover QR display and locally staged PWA handoff; real installed-PWA/browser acceptance, full account lifecycle, cross-device and physical-device checks, deployment/upgrade/rollback, and independent security review remain release gates.

## Data and endpoint behavior

The schema 18 migration removes only retired-feature records and tables: Cinema/media-library sharing overrides, Link Remote sessions/signals, and Sentinel tokens/incidents/events. Accounts, sessions, encrypted messages, contacts, Link identities/pairings/transfers, Vault and Secrets records, audit history, Matrix bindings and backups remain untouched. Fresh databases never create the retired tables. The retained Link proof-store migration is schema 16 → 17; schema 18 then removes the retired tables. Backup verification continues to accept older backup schemas while schema 18 no longer requires retired tables. Additive schema migrations 19–26 add Calendar events, recurring series and workspace sharing, encrypted Share payloads and open limits, Workspace membership/items and one-time/recurring Automate reminders. No running user service or database has been changed by this code work.

This is a code and interface scope change. It does not deploy, publish, or modify a live database. Installing the updated service on an existing database applies schema 18 and permanently removes the retired-feature records listed above, then applies additive schema 19–26. A fresh installation starts without retired-feature tables and with the retained modules.

## Verification

The reconstructed source passes TypeScript, ESLint, all 316 frontend tests across 73 files, all 118 server tests, and the production build. Playwright discovers eight browser specs, including the PWA share-target handoff flow; browser execution is blocked in this workspace because Chromium and Firefox binaries are absent. The build still reports the existing large Matrix bundle warning. API tests assert that retired media and Sentinel paths are not served; Link tests continue to cover device pairing and encrypted payload delivery. Legacy browser tests dedicated to removed screens are retired with those screens.
