## Encrypted Share QR and PWA receive

Date: 2026-10-25. Local commit `11df2b0` adds a downloadable client-generated QR code for the full encrypted bearer link and a Web Share Target for title/text/URL. The service worker bounds encoded input to 5 MB and reviewed content to 1.5 MB, keeps at most ten one-hour handoffs in IndexedDB, and consumes each by one-use UUID. The page receives staged text only after sign-in, reviews it locally, and removes the query token; no shared plaintext is sent to an API. Authentication preserves both the opaque handoff and encrypted-link fragment so sign-in does not discard the destination. UI tests cover QR output and local review staging; an actual service-worker browser spec is added but remains unexecuted because this workspace has no installed browser binary. The browser spec remains an open acceptance item.

The follow-up adds a Node service-worker harness covering input bounds, unsupported forms, ten-item queue eviction, expiry, and one-use deletion. Its first run exposed an IndexedDB transaction result wrapper bug in consumption; the worker now returns the actual record only after transaction completion, and the harness passes. The share-target redirect is explicitly `no-store`. The server suite now has 112 passing tests. Real browser execution remains unavailable locally.

## Nested decrypted Chat search and encrypted text edits

Chat search is a collapsed header disclosure. It matches text and attachment names among up to 200 successfully decrypted messages loaded on this device, keeps terms in component memory, and jumps locally.

The sender can edit an owned decrypted text message from its nested message actions. The edit is a new encrypted event; the target ID and new body remain in ciphertext. Projection requires the edit sender to match the original sender. Attachments and another user's messages are rejected. The sender can also redact an owned encrypted message for everyone from the same nested menu, with a styled confirmation that explains retained backups and saved copies. The deletion controller accepts only the sender’s own encrypted room events, checks the current Locat binding after event lookup, and sends a content-free redaction request. Redacted messages and replies project safe deleted placeholders. Unit coverage checks ownership, forged edits and encrypted send shape; browser coverage exercises the two-account edit and deletion UI and checks that content is not sent in clear text.

## Device app lock

Account → Security now includes a nested device-local app lock. Passcodes are salted and derived with PBKDF2-SHA-256; settings control inactivity timeout and background locking, and users can lock immediately. Lock signals clear other open same-origin app tabs as well. The lock gates the app UI while leaving the server session intact. Browser storage is not encrypted by this feature, and biometrics remain disabled pending verified platform authentication. Focused tests cover passcode verification, setting/policy lifecycle, and hiding/revealing app content through the gate. The built-browser foundation flow now additionally checks reload persistence, wrong-passcode rejection, and correct unlock without storing the passcode in the verifier.

## Link resume file identity and Offline connection diagnostic

Interrupted Link upload resume now computes a keyed HMAC fingerprint over the complete file's chunk hashes before sending any chunk. The key is derived from the account/device ECDH secret and remains non-exportable; the raw file hash is not stored. Existing journals without a fingerprint fail closed with cancel/resend guidance. This catches changed bytes even in chunks that were not uploaded before interruption, while existing saved-ciphertext checks still protect already uploaded chunks. The browser scenario changes a byte in an unuploaded chunk and verifies resume fails before any new chunk write. The first hosted run exposed only a stale request-count assertion (expected 11; actual 12 includes the initial text send); `9118708` corrects it.
