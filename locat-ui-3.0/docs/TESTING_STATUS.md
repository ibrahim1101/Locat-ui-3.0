## Latest — isolated operator SQLite backup verification

Added npm run verify:backup -- <backup.sqlite> [expected-sha256]. The operator-only command copies a stable regular backup through a bounded hash stream into a private temporary directory, then opens only that copy read-only. It checks header, SHA-256 when supplied, SQLite integrity/foreign keys, supported version, required tables and version-appropriate columns; it reports summary counts without raw records. Active journals, symlinks, changed inputs, oversized files, corruption and incomplete/future schemas are rejected. Original input bytes are never repaired/migrated/restored, and temporary copies are cleaned up. Shared schema-version constant fails closed if the verifier manifest falls behind a future migration. Validation: 172 frontend/48 files, 72 backend tests, check/lint/build pass; tests include CLI exit status, old v1 non-migration, checksum mismatch, actual page corruption, orphan foreign keys and unchanged input/directory. SQLite-only verification is not a complete restore/decryption/browser/native/sidecar/media backup certification. Full roadmap and messaging gate remain active. See BACKUP_VERIFICATION.md.
