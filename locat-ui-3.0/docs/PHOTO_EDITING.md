# Live photo editing and undo history

The UI3 Photos editor keeps up to 100 previous edit-parameter states while a photo is open. Shared Undo edit and Redo edit buttons cover crop, rotation, flips, color adjustments, text addition/removal/placement and Reset edits. A new edit after undo discards the redo branch. Reapplying the same parameters does not consume a history step. Moving a slider may create multiple steps; this is bounded step history, not unlimited gesture history. Viewer zoom changes only the view and is excluded from edit history.

History holds immutable parameter objects rather than decoded image copies, generated image blobs or object URLs. The parent keys the viewer by media ID; closing/reopening or selecting another photo starts a fresh history. Undo does not restore an unsaved annotation draft. This history is not persisted across close/reload or synchronized to another device.

Preview and JPEG download use the same currently selected edit parameters. Reset can itself be undone. The imported/source file remains unchanged; edited JPEG copies use the existing maximum 1600-pixel edge and size/quality bounds. Local imported photos remain browser-local plaintext media under the existing storage model; this is not encrypted cloud Photos or a native editing certification. Existing freehand rendering types do not provide a drawing UI; freehand/brush UI and broader photo organization/sync remain planned.

Unit/DOM tests cover bounded history, no-op edits, new-branch redo clearing, reset/annotation recovery, viewer zoom exclusion, selected-state export and original-file preservation. A separate actual Chromium target imports a generated four-by-two PNG, compares canvas pixels after undo, checks redo geometry/annotations, downloads a real JPEG and compares the original PNG bytes after editing. It also verifies that close/reopen drops undo history. That browser target requires its own observed CI success; DOM canvas mocks do not certify actual rendering.
