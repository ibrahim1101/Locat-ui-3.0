# Live photo editing and undo history

The UI3 Photos editor keeps up to 100 previous edit-parameter states while a photo is open. Shared Undo edit and Redo edit buttons cover crop, rotation, flips, color adjustments, text addition/removal/placement and Reset edits. A new edit after undo discards the redo branch. Reapplying the same parameters does not consume a history step. Moving a slider may create multiple steps; this is bounded step history, not unlimited gesture history. Viewer zoom changes only the view and is excluded from edit history.

History holds immutable parameter objects rather than decoded image copies, generated image blobs or object URLs. The parent keys the viewer by media ID; closing/reopening or selecting another photo starts a fresh history. Undo does not restore an unsaved annotation draft. This history is not persisted across close/reload or synchronized to another device.

Preview and JPEG download use the same currently selected edit parameters. Reset can itself be undone. The imported/source file remains unchanged; edited JPEG copies use the existing maximum 1600-pixel edge and size/quality bounds. Local imported photos remain browser-local plaintext media under the existing storage model; this is not encrypted cloud Photos or a native editing certification. The Draw tool uses pointer capture, adjustable brush color/width and normalized image coordinates. Each completed stroke creates one undo step; cancelled or lost-capture gestures discard their draft. Limits are 100 strokes and 1,000 points per stroke. Clear drawing is undoable. Draft previews are scheduled by animation frame, and export is disabled during a draft. Broader photo organization/sync remain planned; physical touch/stylus acceptance is still pending.

Unit/DOM tests cover bounded history, no-op edits, new-branch redo clearing, reset/annotation recovery, viewer zoom exclusion, selected-state export and original-file preservation. A separate actual Chromium target imports a generated 64-by-32 PNG, compares canvas pixels after undo, checks redo geometry/annotations, downloads a real JPEG and compares the original PNG bytes after editing. The expanded drawing target checks cancelled drafts, real green stroke pixels, one-step undo/redo and undoable clearing. It also verifies that close/reopen drops undo history. That browser target requires its own observed CI success; DOM canvas mocks do not certify actual rendering.

The themed Photo information disclosure shows original decoded pixel dimensions, recorded file size, reported Blob MIME type (or Not provided) and device/server source. These are basic file facts, not EXIF extraction: camera, capture date, orientation/GPS fields and timeline inference remain unimplemented. The original dimensions do not change when editing crop or rotation.

Photos tags are optional browser-local metadata, including for read-only server library entries. The Tags sheet accepts up to 20 case-insensitively unique labels of at most 40 UTF-16 code units, strips empty comma-separated entries and rejects embedded control characters. An empty submission clears tags. Names, albums and tags participate in library search. Saved tags are shown from actual library state; the sheet remains open during/after save and displays storage failures rather than implying a completed cloud write. Server files/metadata are not modified, and tags are not backed up or synchronized. Existing IndexedDB records need no migration; missing tags mean an empty list.

Find duplicate photos scans only the currently filtered imported browser-local photos. It reads each original Blob and computes SHA-256 locally; it never fetches server files, uploads bytes or removes copies. Matching hashes are grouped by filename for review; this is file-content comparison, not visual similarity, so recompressed/edited images generally differ. Limits are 500 imported photos, 32 MiB per eligible file and 256 MiB total eligible bytes. Oversized files are explicitly counted as skipped; over-count/total-byte scans require narrower filters. Closing the sheet or leaving the library discards the result and prevents late publication. Cancellation is checked between asynchronous reads/digests; it does not interrupt an already-running native Blob read or Web Crypto digest. No hashes/results are persisted or synchronized.

The Photo library view selector offers Grid and Import timeline. Timeline groups browser-local imports by the viewing browser's local calendar day, newest first; missing/invalid dates appear in Unknown import date at the end. Server entries are excluded because their catalog timestamp is a file modification time, not a browser import or camera capture date. Existing name/album/tag, favorite, source and playlist filters apply before grouping; saving results uses only the visible ordered results. Timeline temporarily orders chronologically without modifying saved playlists or the Grid sort choice. Camera/EXIF capture-date organization, time-zone changes across devices and cloud timeline synchronization remain outside this feature. The view choice is session-local UI state.
