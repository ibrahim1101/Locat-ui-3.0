# Same-origin Matrix sidecar preparation

This is configuration tooling and proxy source, not a running deployment. Docker/PostgreSQL/ARM64 and nginx runtime acceptance are pending. Existing Node-only Locat hosting does not proxy Matrix paths automatically. Account mapping and live chat remain gated as described in MATRIX_INTEGRATION.md.

Repository-root compose.matrix.yml prepares a separate Synapse service with PostgreSQL. Synapse binds only host loopback port 8008; the database has no published port. Both images must be operator-verified pinned versions/digests with the intended architecture. This volume layout expects the official PostgreSQL 18 layout mounted at /var/lib/postgresql; do not point another major version at an existing database volume. Never change database image major versions without a tested backup/migration/restore procedure.

From the app directory, `node tools/prepare-matrix-sidecar.mjs <new-private-directory> <https-origin>` prepares only private files. Choose a directory outside git with the correct operator/container ownership. It creates a new directory mode 0700 and files mode 0600 on POSIX, refuses any existing directory, generates separate database administrator/application passwords plus signing-related server secrets, closes registration/federation/statistics and writes no secret to stdout. It does not start services or create users/DNS. Windows ACLs require separate verification. Check the selected container UID/GID and grant only the needed read permission on its configuration/initialization files; the tool does not weaken permissions automatically.

Generated init.sql creates a dedicated synapse login role with NOSUPERUSER/NOCREATEDB/NOCREATEROLE, owning only its database with UTF8/C locale. The administrator password is a separate private Compose secret. Configuration and init.sql contain the application password and must remain private. Initialization files apply only to a new PostgreSQL data directory. Keep server signing keys and PostgreSQL backups; client recovery keys require their own design. Do not overwrite existing configurations or replace lost credentials by generating a different directory against an existing database.

Set LOCAT_MATRIX_CONFIG_DIR to the private directory, LOCAT_MATRIX_IMAGE to the reviewed Synapse image, and LOCAT_MATRIX_POSTGRES_IMAGE to a reviewed PostgreSQL 18 image. The user has not approved activation; do not run the stack or public routes as part of source preparation. Validate Compose, image architecture/user permissions, actual private listener, database role grants, generated configuration loading and consistent backup/restore on isolated hardware first.

`deploy/matrix/nginx-locations.conf.example` is intended for the existing exact-host HTTPS server block. It routes only Matrix client/media API prefixes to private Synapse and strips Cookie, while preserving Matrix Authorization. Synapse authenticates Matrix bearer tokens separately; these routes do not establish a Locat account binding. Administrative/federation/key paths return 404. Keep existing Locat Host/Origin enforcement and exact public origin. Preserve all unrelated server/domain routes. The current Cloudflare template routes straight to Node and would require an explicitly approved routing change to a suitable proxy before serving this sidecar; no such change was made.

Do not copy the synthetic acceptance harness's open registration into this profile. Production account provisioning/token exchange, device mapping/revocation, verification UX and recovery must be designed before enabling live Messages. This sidecar is not a second unrelated frontend. Future clients use the shared same-origin deployment while maintaining separate cryptographic identities until explicitly authorized mapping is implemented.

Validation performed: generated-file tests verify strict HTTPS origin, private modes, closed registration/federation, separate passwords, restricted database role source and refusal to overwrite. The Compose/nginx runtime has not run; this does not certify public-beta readiness.
