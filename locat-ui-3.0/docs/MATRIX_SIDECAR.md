# Same-origin Matrix sidecar preparation

This is configuration tooling and proxy source, not a running deployment. Docker/PostgreSQL/ARM64 and nginx runtime acceptance are pending. Existing Node-only Locat hosting does not proxy Matrix paths automatically. Account mapping and live chat remain gated as described in MATRIX_INTEGRATION.md.

Repository-root compose.matrix.yml prepares a separate Synapse service with PostgreSQL. Synapse binds only host loopback port 8008; the database has no published port. Both images must be operator-verified pinned versions/digests with the intended architecture. This volume layout expects the official PostgreSQL 18 layout mounted at /var/lib/postgresql; do not point another major version at an existing database volume. Never change database image major versions without a tested backup/migration/restore procedure.

From the app directory, `node tools/prepare-matrix-sidecar.mjs <new-private-directory> <https-origin> [locat-instance-uuid]` prepares only private files. The tool requires a directory outside this repository, resolving parent symlinks before checking; choose correct operator/container ownership. It creates a new directory mode 0700 and files mode 0600 on POSIX, refuses any existing directory, generates separate database administrator/application passwords plus signing-related server secrets, closes registration/federation/statistics and writes no secret to stdout. It does not start services or create users/DNS. Windows ACLs require separate verification. Check the selected container UID/GID and grant only the needed read permission on its configuration/initialization files; the tool does not weaken permissions automatically.

Generated init.sql creates a dedicated synapse login role with NOSUPERUSER/NOCREATEDB/NOCREATEROLE, owning only its database with UTF8/C locale. The administrator password is a separate private Compose secret. Configuration and init.sql contain the application password and must remain private. Initialization files apply only to a new PostgreSQL data directory. Keep server signing keys and PostgreSQL backups; client recovery keys require their own design. Do not overwrite existing configurations or replace lost credentials by generating a different directory against an existing database.

Set LOCAT_MATRIX_CONFIG_DIR to the private directory, LOCAT_MATRIX_IMAGE to the reviewed Synapse image, and LOCAT_MATRIX_POSTGRES_IMAGE to a reviewed PostgreSQL 18 image. The user has not approved activation; do not run the stack or public routes as part of source preparation. Validate Compose, image architecture/user permissions, actual private listener, database role grants, generated configuration loading and consistent backup/restore on isolated hardware first.

`deploy/matrix/nginx-locations.conf.example` is intended for the existing exact-host HTTPS server block. It now routes Matrix client/media prefixes to the Locat gateway, forwarding the browser Locat cookie/device proof and Matrix bearer only to Node. Node strips cookies before the fixed upstream request and enforces account/device binding. The bootstrap gateway deliberately gates conversation/media mutation. See MATRIX_ACCOUNT_BINDING.md. Administrative/federation/key paths return 404. Keep existing Locat Host/Origin enforcement and exact public origin. Preserve all unrelated server/domain routes. The current Cloudflare template routes straight to Node and would require an explicitly approved routing change to a suitable proxy before serving this sidecar; no such change was made.

Do not enable open registration in this profile. Production account provisioning/token exchange, device mapping/revocation, verification UX and recovery must be designed before enabling live Messages. This sidecar is not a second unrelated frontend. Future clients use the shared same-origin deployment while maintaining separate cryptographic identities until explicitly authorized mapping is implemented.

Validation performed: generated-file tests verify strict HTTPS origin, private modes, closed registration/federation, separate passwords, restricted database role source and refusal to overwrite. The Compose/nginx runtime has not run; this does not certify public-beta readiness.

Primary references checked 2026-10-15: https://hub.docker.com/_/postgres (18 data-directory layout, initialization variables); https://element-hq.github.io/synapse/latest/postgres.html (database preparation); https://element-hq.github.io/synapse/latest/setup/installation.html .

Optional managed-account preparation: supply the existing stable Locat instance UUID as the third argument to generate a private `locat-appservice.json` and reference it in Synapse configuration. The exclusive namespace includes only this instance's 32-hex account IDs; no room/alias namespace or event receiver is configured. AS/HS credentials are distinct and server-only. This prepares new private files without activating the service. Do not regenerate an instance UUID or silently replace an existing registration. A strict registration validator now rejects foreign instance identities, broader user/room/alias scopes, event receivers, shared credentials and disabled rate limiting. The validator is not yet connected to a production provisioning endpoint.

Real isolated Synapse 1.163.0 acceptance now uses passwordless application-service registration and device login. Ordinary registration cannot take the reserved identity; out-of-namespace service registration fails with M_EXCLUSIVE. The service token never enters SDK client configuration. This proves protocol feasibility, not live Locat SSO, persistent browser recovery or production activation. Application-service credentials can impersonate managed identities inside their namespace and must remain private; peer verification and client key protection remain necessary.

A server-only private registration loader now reads at most 16 KiB, rejects symbolic links and nonregular files, validates exact instance/namespace scope and requires no group/world POSIX access. Error messages omit file content and credentials. Windows ACL acceptance is still pending. The loader is not yet wired into live provisioning.

## Managed provisioning follow-on

After separately validating/activating the private Synapse registration, an operator may configure Node with `LOCAT_MATRIX_APPSERVICE_FILE` pointing to that same private JSON file. Startup fails closed if the sidecar is missing or the registration fails private-file/instance/scope validation. Source changes alone activate no services. No raw AS credential environment variable or public settings field is supported.

The authenticated `/api/link/matrix/provision` POST accepts only `{}`; the Locat cookie, exact Origin and current device proof determine account and device IDs. Standard service registration/login is bounded to the fixed upstream, a 10-second provisioning deadline, 32 KiB responses, eight concurrent operations and one per account/device. Existing incompatible mappings or unknown/changed published keys require explicit migration/recovery. Browser Rust keys must still pass the separate binding endpoint before gateway access. Session/proof ownership is rechecked between upstream steps and after validation. A newly minted token is logged out on failure; an unconfirmed cleanup is reported honestly. No raw token is persisted in Locat SQLite.

The UI3 setup sheet exposes an explicit managed submit action only when configuration reports it available; separate credential fields are then omitted. A dedicated operation client permits cleanup after sheet closure. Failed initialization/binding calls `cancel-provision`, which inspects the supplied normal device token, verifies the exact derived managed identity and confirms upstream logout. Cleanup has a separate bounded rate bucket. Authorization loss can prevent browser cleanup; server rechecks also notice a disconnected request and attempt logout. A network drop after the final response check can still leave an upstream session: all-session inventory/revocation and token-expiry policy remain open requirements. Closing a successfully bound sheet releases local crypto without claiming upstream logout.

Real Synapse acceptance exercises the same provisioning module plus managed token cancellation; UI tests exercise explicit setup, omitted credentials, initialization failure and late-close cleanup. Actual HTTPS browser IndexedDB/WASM, operator stack runtime, recovery, verification UX and conversations are not certified by these tests.
