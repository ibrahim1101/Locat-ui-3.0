# Messaging security model and implementation gate

Private messaging remains disabled in live UI. The legacy /api/messages API is gated on the backend: authenticated GET/POST return 501 MESSAGING_SECURITY_GATE, unauthenticated access returns 401, and mutating Origin checks remain. No flag bypasses this gate. Existing experiment rows remain in SQLite/backups. Its durable ciphertext storage does not establish key authentication, forward secrecy, ratchets, group membership or device revocation. Replace the gated experiment only after reviewed protocol integration acceptance.

Evaluation (official upstream documentation checked 2026-10-15): matrix-js-sdk supports browser/Node clients and initRustCrypto with a persistent browser crypto store, cross-signing and backup APIs. It warns against multiple clients using the same IndexedDB crypto store. This makes a full Matrix stack the preferred integration candidate for browser plus standards-based federation. SDK 44.0.0 is now pinned, with an actual loopback Synapse/Rust-crypto acceptance harness. See MATRIX_INTEGRATION.md for exact passed checks and limits. Distribution obligations and independent security review remain separate. Multi-tab single-writer ownership is mandatory.

libsignal provides Rust-backed Java/Swift/TypeScript bindings, but upstream explicitly does not support use outside Signal and permits API/bridge changes. It carries AGPLv3 terms. It is not a drop-in browser messaging backend or federation stack. The feasibility direction favors Matrix; no claim of equal post-compromise guarantees across protocols is made. Verify exact selected SDK/homeserver licenses and notices before distribution.

Local synthetic encryption, out-of-band fingerprint comparison, durable offline delivery after server restart, ciphertext-tamper rejection and timeline duplicate suppression now pass. Next gate: Locat account/token mapping, browser persistence/verification UX, group changes, comprehensive replay/key rotation/revocation and backup/recovery tests. Inspect databases/logs for plaintext/private keys. Test altered keys, stale devices, malicious server responses and attachment tampering. Do not enable Send until these pass. No independent audit has occurred.

Metadata boundary: a homeserver still observes accounts, device/public keys, routing, membership, timing, sizes and delivery information appropriate to the chosen protocol. TLS termination can read server-visible metadata and ordinary profile/media APIs. Link ECDH and Vault encryption do not certify messaging. Browser compromise/XSS or a maliciously served client can compromise client keys; origin isolation is necessary but insufficient.
